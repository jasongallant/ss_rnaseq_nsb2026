Welcome to the workshop server

You are logged into a shared RStudio server at workshop.efishgenomics.com. The server has Seurat, DESeq2, Harmony, propeller, and everything else you’ll need pre-installed. You’ll do all of Friday’s and Saturday’s hands-on work here — no need to install anything on your laptop.

Each of you has a personal home directory (~/ssrnaseq/) populated from the workshop’s golden image. The same lesson content sits in every student’s home; what you change in yours stays in yours.

WarningThe website and the workbook are different files

The rendered episodes (episodes/snrnaseq-preprocessing.Rmd) are the answer keys — they contain complete, runnable code with full explanations. They also appear on the course website at tutorials.efishgenomics.com.

The workbooks (episodes/workbook/snrnaseq-preprocessing.Rmd) are your working surface. They have the same overall structure, but with key decision points gapped out (___) and predict-first prompts before each one. You work in the workbook. When stuck, consult the rendered episode.

Open the workbook

In the Files pane, navigate to episodes/workbook/ and double-click snrnaseq-preprocessing.Rmd. It opens as an R Notebook in the Source pane.

WarningDon’t click ‘Render’ or ‘Knit’ on the workbook

Workbooks are R Notebooks — they’re meant to be run chunk by chunk, interactively. Clicking the Render or Knit button tries to execute every chunk in sequence, which will fail at the first ___ gap. Instead:

  • Run a single chunk with the green ▶ button (top-right of the chunk) or Cmd-Shift-Enter / Ctrl-Shift-Enter.
  • Run all chunks up to here with the small downward triangle to the left of the ▶.
  • Output appears inline below the chunk.

The ___ gap convention

When you see ___ in a workbook chunk, that’s a decision point you have to fill in:

n_pcs <- ___
merged_seurat <- RunUMAP(merged_seurat, dims = 1:n_pcs)

If you run the chunk with ___ left in place, R errors out — by design. The error reminds you that this line is a place to think, not a line to skim.

The chunks with ___ also have eval=FALSE set in their chunk options. That means they’re skipped if you try to render the whole notebook in one go — another guardrail against accidental “I clicked Knit and now everything broke” moments.

The predict-first prompts

Before most gapped chunks there’s a blockquote like this:

Predict first. Looking at the elbow plot, where do you think the curve flattens — around PC 15? PC 25? Write your guess before running any code.

Your prediction:

These exist because the analytical skill we’re building is judgment, not typing. Predict, run, compare. If your prediction was wrong, the discrepancy is the most valuable feedback in the lesson.

The checkpoint-load idiom

Each major preprocessing step is slow (SCTransform takes a few minutes; Harmony takes about a minute). If you make a mistake mid-pipeline and want to recover without re-running everything, load the previous checkpoint:

merged_seurat <- readRDS("data/checkpoints/01_merged_sct.rds")

The checkpoints shipped with the AMI are the canonical state. If you’ve been making progress and want to save your own checkpoint mid-session, write to a different name so you don’t overwrite the shipped ones:

saveRDS(merged_seurat, "data/checkpoints/my_temp_state.rds")
TipIf Saturday catches you cold

If you missed Friday entirely, the first chunk of episodes/workbook/snrnaseq-annotation-and-de.Rmd loads the shipped 02_harmony_clustered.rds and you can join Saturday’s session with a known-good entry state. The same trick works mid-Saturday: if your annotation gets tangled, load 03_annotated.rds.

Quick smoke test (5 min)

Try this now to confirm everything works end-to-end:

# 1. Load Seurat
library(Seurat)

# 2. Load the shipped Friday checkpoint
seu <- readRDS("data/checkpoints/02_harmony_clustered.rds")

# 3. Confirm it loaded and inspect basic metadata
seu
table(seu$treatment)

If you see a Seurat object with 4 samples, ~10,000 nuclei, and treatment labels (11kt, vehicle), you’re good to go. If you see an error, raise a hand — we’ll fix it before starting the Friday code episode.

Keypoints

  1. Your working surface is episodes/workbook/*.Rmd. The rendered episodes are answer keys you consult when stuck.
  2. Run chunks one at a time — never click “Render” or “Knit” on a workbook.
  3. ___ is a decision point. Fill it in based on the prediction prompt above it.
  4. Checkpoints in data/checkpoints/ let you skip past slow steps or recover from mistakes — load with readRDS().
  5. Raw data and QC reports live on a shared mount; you don’t need to copy or download anything.
